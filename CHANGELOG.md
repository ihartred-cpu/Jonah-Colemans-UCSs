## 2026-07-31 — Second real CV test result: Revision 21 fix, the actual root cause

- User confirmed the `L?VBORE` precondition works (adding shelves produced `Front Line Bore (LFVBORE)`
  / `Rear Line Bore (LRVBORE)`), and confirmed the part-level attributes (`JCS_ShelfStd_Use`,
  `JCS_ShelfStd_LengthType`, `JCS_ShelfStd_Length_Over`) show up correctly on the part — but still no
  dado or visual part was ever created.
- Root cause, found by re-checking the raw paste directly: the `;operations only from here on down`
  block, which computes and *stores* `JCS_Use_ShelfStd` on the part so operations can read it back via
  `:JCS_Use_ShelfStd`, had been placed *after* `if OBJECT == 17 then ... end if` closed in the
  Revision 19/20 reconstruction, instead of inside it as the raw paste actually has it. That meant the
  value was never stored on the part, so every operation's `:JCS_Use_ShelfStd == 0` check read
  null/undefined and exited immediately — matching exactly what was observed.
- Fixed in Revision 21: moved the block back inside `OBJECT == 17`, matching the raw paste exactly.
- Updated README.md and TESTING.md #2 with the full three-round story.

## 2026-07-31 — Item 5 root cause found: Centerline Route fixed in Revision 22

- User ran TESTING.md item 5 in CV: setting `ucs_Operation_Type` to "Centerline Route" produced a line
  in the assembly view, but nothing showed up on the CAM Reports/nest list — confirmed via a real CAM
  Reports screenshot of the dado-mode part for comparison (`Shelf Standard - Front`/`Back` entries).
- Root cause, not what Revision 10's own comment described ("gets dim'd as a dado"): the route branch
  used `dim ShelfStandardDado as new line` — `line` is a non-cutting visual/dimension object in CV's
  object model, not a machinable operation type — with its width hardcoded to
  `ShelfStandardDAdo.DX := 0` (also a stray case typo on the variable name). It was never going to nest
  regardless of what else was right.
- Fixed in Revision 22: switched the route branch to `dim ShelfStandardDado as new route` with
  `_RCUT := 1`, the object type this shop's own casework-wall scripts use for a real machined slot
  (`WireChaseRectangle`, `REMOVABLEPANEL`); gave it a real `DX` width matching the dado branch instead of
  0; and extended the centerline-to-corner X/Y offset (previously dado-only) to both branches so the
  now-wider route stays centered on the shelf-standard line instead of shifting a half-width off it.
- **Not yet re-verified against real CV2025 output** — updated TESTING.md #5, README.md, and the
  script's own revision history to flag this as fixed-but-untested.

  the file header says `REV 17`, but the shipped revision history at the foot of the file runs

  which are operations, despite the comment's wording. The real Part/Operation boundary is the `end if`
  seven lines later. Not a functional bug — the code runs fine either way — but worth flagging for anyone
  reading the script cold, since the comment reads as a boundary marker and isn't quite one.
